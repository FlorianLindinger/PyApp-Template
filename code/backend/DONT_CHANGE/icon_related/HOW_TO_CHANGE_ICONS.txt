=======================================
==== HOW TO GENERATE ICONS =========
=======================================

TLDR:
Replace icon.png in code/icons/ with the image you want and run:

    code/icons/regenerate icons.lnk

You can also replace these overlay PNGs in code/icons/ if you want custom sub-icons:

    settings.png
    stop.png
    log.png
    success.png
    failure.png
    crash.png
    crash_log.png
    open_main_py.png

The icon generator creates these .ico files in code/icons/:

    icon.ico
        Icon version of icon.png.

    settings.ico
        Icon version of icon.png with settings.png overlaid in the bottom-right corner.

    stop.ico
        Icon version of icon.png with stop.png overlaid in the bottom-right corner.

    log.ico
        Icon version of icon.png with log.png overlaid in the bottom-right corner.

    success.ico
        Icon version of icon.png with success.png overlaid in the bottom-right corner.

    failure.ico
        Icon version of icon.png with failure.png overlaid in the bottom-right corner.

    crash.ico
        Icon version of icon.png with crash.png overlaid in the bottom-right corner.

    crash_log.ico
        Icon version of icon.png with crash_log.png overlaid in the bottom-right corner.

    open_main_py.ico
        Icon version of icon.png with open_main_py.png overlaid in the bottom-right corner.

The shortcut generator uses those .ico files for the generated program shortcuts.

=======================================
==== INPUT FILES ======================
=======================================

User-editable input images:

    code/icons/icon.png
    code/icons/settings.png
    code/icons/stop.png
    code/icons/log.png
    code/icons/success.png
    code/icons/failure.png
    code/icons/crash.png
    code/icons/crash_log.png
    code/icons/open_main_py.png

Keep the file names unchanged.

If an input PNG is missing, the generator uses the matching fallback image from:

    code/DONT_CHANGE/icon_related/default_icon.png
    code/DONT_CHANGE/icon_related/default_settings.png
    code/DONT_CHANGE/icon_related/default_stop.png
    code/DONT_CHANGE/icon_related/default_log.png
    code/DONT_CHANGE/icon_related/default_success.png
    code/DONT_CHANGE/icon_related/default_failure.png
    code/DONT_CHANGE/icon_related/default_crash.png
    code/DONT_CHANGE/icon_related/default_crash_log.png

The open_main_py overlay is configured too. Add default_open_main_py.png in this folder before generating open_main_py.ico.

If a user image is still exactly the template fallback image, the generator also treats it as fallback.

=======================================
==== GENERATION =======================
=======================================

Run this shortcut:

    code/icons/regenerate icons.lnk

It launches:

    code/DONT_CHANGE/backend_python/python.exe code/DONT_CHANGE/icon_related/generate_icons.py

The generator uses Windows PowerShell/WPF to create multi-resolution .ico files with
these sizes:

    256, 128, 64, 48, 32, 16

It checks all existing user PNGs in one PowerShell process and renders all available
icons in a second process, avoiding the repeated PowerShell startup cost of rendering
each icon separately.

Sub-icon size is configured in generate_icons.py with:

    SUBICON_AREA_SCALE_FACTOR = 0.35

This is an area ratio: 0.35 means a sub-icon occupies 35% of the base image's area.
The generator uses the square root of the ratio when scaling width and height, while
preserving the sub-icon's aspect ratio. Sub-icons are placed in the bottom-right corner.

If a configured overlay or its fallback PNG is missing, that one .ico file is reported
as an error and skipped; the remaining icons are still generated.

Icons should be generated this way instead of with a quick online converter, because
Windows icons need multiple embedded sizes to scale well in shortcuts, taskbar entries,
and Explorer.
=======================================
==== PILLOW / PIL ALTERNATIVE =========
=======================================

The supported generator is generate_icons.py. It intentionally uses Windows WPF so the
project does not need Pillow and icon rendering stays consistent with Windows.
